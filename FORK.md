# How this fork differs from Go protocol buffers v1.36.11

This module is a fork of [Go protocol buffers](https://github.com/protocolbuffers/protobuf-go)
(`google.golang.org/protobuf`) at tag v1.36.11 (BSD 3-Clause, see LICENSE
and PATENTS). It exists so that code generated by `protoc-gen-go`, etcd
raft's in particular, can be built under raftseg's dependency policy:
first-party modules only, each requiring nothing.

The fork is made by a program, not by hand. `internal/tools/prune` writes
every file taken from upstream, from a clean checkout of an upstream
release, and lists them in `upstream-files.txt`. CI runs it again on the
release in `upstream.json` and fails if anything changes. So the tree is
always exactly upstream's, transformed as described below, and following a
new release does not involve merging.

## What is kept

**The runtime and what protoc plugins need.** The packages that
generated code and etcd raft import (`proto`, `encoding/protowire`,
`reflect/protoreflect`, `reflect/protoregistry`, `runtime/protoiface`,
`runtime/protoimpl`), those a protoc plugin needs to read descriptors and
answer protoc (`encoding/prototext`, `reflect/protodesc`,
`types/descriptorpb`, `types/dynamicpb`, `types/gofeaturespb`,
`types/pluginpb`; raftseg/protobuf-go-lite's code generator uses them),
and every package they import: 33 packages, about 44,000 lines, with
upstream's tests and test data. The set is computed with each build flag
that selects other files (`-tags=protolegacy`, `-tags=protoreflect`,
`-race`), so that every variant upstream tests builds.

**What those tests need.** Every package the runtime's tests import, and
everything those import: generated test messages
(`internal/testprotos/...`), the well-known types, `encoding/protojson`,
`testing/protocmp`, `testing/protopack`, `testing/prototest` and others,
56 packages in all. They are kept without
their own tests and test data, which would pull in most of the rest of
upstream. They are used by tests only.

**go-cmp.** `github.com/google/go-cmp` v0.7.0, which upstream's tests use
(through `testing/protocmp` too), is copied into `internal/gocmp`, without
its tests. It is used by tests only.

**Upstream's LICENSE and PATENTS**, and its README as UPSTREAM-README.md.

## What is left out

Everything else: the `protoc-gen-go` plugin and `compiler/protogen`,
`encoding/protodelim`, `protoadapt`, `reflect/protopath` and
`reflect/protorange`, the generators and tools under
`internal/cmd`, benchmarks, fuzz targets of the packages left out,
conformance testing, upstream's integration test and release scripts, and
its CI configuration. Generating code needs upstream's `protoc-gen-go`; the
code it generates then builds against this fork once its imports are
rewritten.

`go.mod` no longer requires `github.com/golang/protobuf`. Upstream
requires it only through `internal/weakdeps` (built with the
`weak_dependency` tag), to make programs that use both APIs take a version
of the old one that wraps the new. The old API is not used with this fork.

## Changes to upstream's files

- **Import paths** of `google.golang.org/protobuf` and
  `github.com/google/go-cmp/cmp` are rewritten to this module, in Go files
  outside `testdata`. Each such file says so in its header. Nothing else is
  changed. Strings in `.proto` sources and in the descriptors embedded in
  generated code (such as `go_package` options) still name upstream's paths;
  they are not used to find packages at run time.
- **`go.mod`** declares this module and upstream's Go version, and nothing
  else.

## Fixes

**A map entry could panic the decoder (`proto/decode.go`).** Decoding a
map entry that holds a key and then a key of another wire type left the
key invalid while still recording it as present, and the entry then
panicked in `MapKey` ("type mismatch: cannot convert nil to map key").
Any program that decodes untrusted input into `dynamicpb` messages with
map fields could be crashed this way: they take the reflection path
(`UnmarshalOptions.unmarshalMap`). Generated code takes another path
(`internal/impl.consumeMap`), which reads the key into a temporary and
was not affected; the fix does the same. The bug is in upstream's
v1.36.11 and in its master branch as of October 2026.
raftseg/protobuf-go-lite's differential test found it. Test:
`proto/fork_map_test.go`, which panics on upstream's code.

## Checks

The fork's own packages (`internal/depcheck`, `internal/tools/...`) pass
`go vet`. Upstream's code is kept as it is, and fails three of vet's
analyzers, so CI runs those with them turned off:
- `composites`: upstream's tests write `protopack.Tag` and other imported
  structs without field names, hundreds of times.
- `copylocks`: `internal/impl/legacy_message.go` appends a `filedesc.Field`
  by value. The `sync.Once` it contains is copied before first use, so the
  copy is harmless.
- `unreachable`: `encoding/prototext/decode.go` has a `return` after a loop
  that never ends.

Upstream runs `go vet` on its generated test messages only.

## Updating to an upstream release

```
git fetch upstream tag vX.Y.Z
git worktree add --detach /tmp/upstream vX.Y.Z
git merge -s ours --no-commit vX.Y.Z    # keep upstream's history as an ancestor
go run ./internal/tools/prune -upstream /tmp/upstream
go test ./...                           # and the rest of README.md, Testing
git add -A && git commit
```

`prune` removes the files the previous run wrote, writes the new ones,
sets the version, commit and sum in `upstream.json` (and empties
`cherryPicked`), and fails if the release imports a third-party module
other than go-cmp, or if a patch no longer applies: then check whether
the release fixed the bug, and drop or redo the patch. Update the version
named in README.md and this file.
Review the diff of the 33 packages kept with their tests; the rest is
used by tests only.

## Additions

Tests of the fork's own go in files of their own (not named as any
upstream file, which `prune` refuses to overwrite), and are kept across
updates: `proto/fork_map_test.go`, the regression test of the fix above.
